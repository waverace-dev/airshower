# Governance

Airshower is currently an experimental project maintained by [waverace-dev](https://github.com/waverace-dev), with no standards-body status or vendor endorsement.

## How decisions happen

1. Open an issue describing a user need, compatibility problem, or security concern.
2. Propose an RFC or pull request with examples and observable acceptance criteria.
3. Discuss effects on independent implementations, consent, privacy, and migration.
4. Maintainers record the decision publicly. Rejected proposals should retain a reason.

Anyone may implement the specification or propose changes. Participation is open to individuals, companies, and frontier model labs on the same terms. Contributions use the repository's Apache-2.0 license; there is no provider exclusion, paid membership, or contribution assignment requirement. Contributors must have the rights to contribute their work.

## Compatibility and releases

The `0.x` profile is unstable. Breaking changes require a version change, changelog entry, and migration note. Specification claims must match tests and advertised capabilities. Implementations must distinguish unsupported operations from successful execution.

We will not label the profile stable until at least two independently maintained implementations demonstrate interoperable behavior, including denial and revocation cases. This is a proposed release criterion, not a claim of current adoption.

## Shared stewardship

As independent maintainers join, establish a public maintainer roster, review rules, conflict-of-interest disclosures, and a transparent process for adding or removing maintainers. Foundation stewardship can be considered when there is a functioning community. No future governance transfer is promised.
